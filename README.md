# OpenCapture

무료 GPL-3.0 캡처 앱. eSearch를 기반으로 Windows부터 개발하고 있습니다. **현재는 개발 프리뷰이며 Tracer 전체 기능 동등성 검증이 끝난 정식 릴리스가 아닙니다.**

## 실행

전체 편집기에 컬러 글래스 테마를 적용했습니다. 홈·라이브러리·번역·설정·단축키 창과 축소 화면이 같은 디자인을 사용합니다. [디자인 변경과 다음 개선 목록](docs/DESIGN_IMPROVEMENTS.md), [디자인 기준](DESIGN.md)을 참고하세요. 경량 캡처 도우미의 바이너리는 이번 시각 변경으로 수정하지 않았습니다.

평소에는 **`release/win-unpacked/OpenCaptureQuick.exe`**를 실행하세요. 작은 Windows 도우미가 트레이에서 대기하고 영역 캡처·PNG 저장을 직접 처리합니다. 캡처만 할 때는 Electron 편집기를 실행하지 않습니다. 편집기는 Ctrl+Shift+Space로 열고 닫습니다. 자동 누끼·복사·고정을 켠 경우에도 원본부터 저장한 뒤 필요한 처리만 요청합니다.

전체 편집기는 `OpenCapture.exe`이며 같은 폴더의 DLL과 `resources`가 필요합니다. **기본 캡처만 필요한 최소 배포본**은 `release/OpenCapture-Quick-Windows.zip`으로, 소스와 GPL 라이선스도 포함합니다. 최소 배포본에는 OCR·녹화·번역·누끼 엔진이 없으므로 전체 기능은 같은 폴더의 전체 편집기가 필요합니다.

로그인 시 시작은 설정에서 선택할 수 있습니다. 개발 중 사용자 시작 설정을 임의로 켜지 않았습니다. 도우미를 종료하면 전역 단축키도 해제됩니다.

- 홈: 영역·전체 화면·창·스크롤 캡처, 녹화, OCR, 화면 번역, 클립보드 이미지 고정
- 라이브러리: 파일 드롭, 컬렉션, 여러 장 선택·일괄 내보내기·고정·가로/세로 합치기. 목록을 1,000개에서 잘라내지 않으며 처음 80개만 불러옵니다.
- 캡처 후 자동 작업: 원본 보존 → 선택적 누끼 → 결과 복사/고정. 누끼 실패 시 원본으로 후속 작업을 수행하고 오류를 보관합니다. 기본값은 모두 꺼짐입니다.
- 간단히/펼치기: 작은 패널로 전환합니다. 숨기면 렌더러를 해제하고, 도우미로 연 편집기는 모든 창과 작업이 끝난 후 종료합니다.
- 번역: 모델 설치 버튼을 한 번 누르면 영어↔한국어 모델을 내려받습니다. 이후 번역은 로컬에서 처리합니다. 약 270MB의 모델 공간이 필요합니다.
- 설정: 선택적으로 본인의 DeepL 또는 Google API 키를 저장할 수 있습니다. API 사용료는 각 제공자 정책을 따릅니다. 앱은 사용료를 청구하지 않습니다.

## 단축키

| 동작 | 단축키 |
|---|---|
| 영역 캡처 | 도우미 Ctrl+Shift+A, 충돌 시 Ctrl+Alt+A |
| 녹화 영역 선택 | Ctrl+Shift+R |
| 편집기 열기/닫기 | Ctrl+Shift+Space, 충돌 시 Ctrl+Alt+Space |
| 드래그 중 드롭존 | Ctrl+Shift+D |
| 선택된 글자 번역 | Ctrl+Alt+T |
| 고정 이미지 포커스·깜빡임·클릭 통과 복원 | Ctrl+Alt+Esc |

도우미의 캡처·토글을 제외한 고급 기능 키는 편집기가 실행 중일 때 동작합니다. 실제 등록 키와 충돌 상태는 트레이/설정에 표시됩니다. 다른 앱이나 Windows의 키를 빼앗지 않으며 기존 단축키 설정을 지우지 않습니다.

캡처 선택 화면에서 실시간 번역을 켤 수 있습니다. 로컬 모델의 속도에 따라 지연될 수 있습니다. 고정 이미지 툴바에서 포커스와 깜빡임 비교를 사용할 수 있습니다.

## 확인된 결과와 한계

- Windows 배포 실행 파일의 시작 화면과 내장 Python 번역 엔진 동작을 확인했습니다.
- 상태 관리·실시간 번역·IPC·워크플로우·단축키·시작 명령 테스트 22개와 자산 무결성 테스트 4개가 통과했습니다. Windows 도우미의 충돌 등록/해제 및 합성 캡처·원본 보존 테스트도 통과했습니다.
- 1,005개 목록으로 조회, 추가 저장, 픽셀 기준 합치기, 자동 누끼 원본 보존, 축소 UI, 편집기 종료를 확인했습니다. 캡처 전달 목록의 중복 처리·원래 컬렉션/시간 보존·잘못된 요청 격리도 확인했습니다.
- 최신 도우미 파일은 27,648바이트이며 이 PC 표본에서 대기 작업 메모리 약 31MiB, 등록 준비 약 87–155ms였습니다. 실제 캡처 지연이나 전체 편집기의 설치 용량을 뜻하지 않습니다. 전체 편집기는 Chromium·영상·번역 런타임 때문에 여전히 큽니다.
- 영어 OCR 샘플은 정확히 인식했습니다. 한국어 샘플의 `캡처`를 `럽처`로 오인식해 정확도 개선이 필요합니다. 한국어 OCR 모델은 고급 설정에서 선택할 수 있습니다.
- 배경 제거는 U2NetP로 투명 PNG를 생성하며 합성 이미지에서 알파 채널을 확인했습니다. 자연 사진의 경계 품질은 추가 검증이 필요합니다.
- 에이전트 실행 환경에서 화면 캡처 API는 잘못된 핸들 또는 검은 화면을 반환했습니다. 사용자 데스크톱이 잠기지 않았다는 확인을 받았으며, 원인을 잠금으로 단정하지 않습니다. 실제 화면 캡처·스크롤 결합·녹화·다중 모니터/DPI는 사용자 데스크톱에서 추가 검증해야 합니다.
- 추가 진단에서 작업 스레드의 데스크톱은 `Default`, Windows 입력 데스크톱은 `Screen-saver`로 보고됐습니다. 입력 데스크톱 전환이나 잠금 우회를 시도하지 않았습니다.
- 웹 이미지 URL 드롭, 선택 중 연속 번역의 전체 흐름, 일부 고급 편집·녹화 기능은 아직 검증 중입니다. 일부 고급 UI에는 영어/중국어가 남아 있습니다. macOS는 이번 빌드에서 검증하지 않았습니다.
- 전체 기능 검증 목록은 `.omx/plans/feature-ledger-capture.md`, 로컬 검사 결과는 `.evidence/`에 있습니다. 디지털 서명은 적용하지 않았습니다.

## 개발

벤치마킹 근거와 다음 개선 후보: [docs/BENCHMARKS.md](docs/BENCHMARKS.md). 캡처 기본 경로와 편집/AI 경로를 나누어 상주 부담을 줄였으며, 새 npm/NuGet 의존성을 추가하지 않았습니다.

Node.js 24, pnpm 10.17.0, Windows x64를 기준으로 작업했습니다. 번역 런타임을 준비할 때만 개발용 Python 3.12가 필요하며, 배포 앱은 내장 Python을 사용합니다.

```powershell
npx --yes pnpm@10.17.0 install --frozen-lockfile
node node_modules/electron/install.js
python -X utf8 scripts/prepare-translation.py
npm run prepare:assets
npm run typecheck
npm run lint
npm test
node --test scripts/assets.test.cjs
npm run build
npm start
npm run pack:windows
```

`scripts/verify-package.cjs`는 배포 실행 파일의 UI·로컬 번역을 확인합니다. 테스트 모델은 `.omx/smoke-models-phase0`에서 별도 테스트 프로필로 복사하며 배포물에 포함하지 않습니다. 최초 환경에서는 먼저 모델 설치가 필요합니다.
