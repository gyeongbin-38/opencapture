# 贴图

贴图需要置于顶层、可缩放、可移动、可调节透明度、可鼠标穿透，还需要管理其他贴图（取消穿透的贴图）。

首先自然想到使用`BrowserWindow`暂时每一张贴图，但在缩放时网页反应不及时，透明窗口在 Windows 下无法调节大小。

所以我们只能考虑通过 web 绘制每一张贴图的窗口（不考虑额外语言或技术的实现）。

我们需要创建一个透明的全屏置顶窗口，通过主进程发送的图片和坐标（来自截屏）来绘制每一张贴图。

为了模拟窗口效果，我们只允许贴图接收鼠标事件，无贴图的位置鼠标穿透。见[主进程-透明窗口](main.md#透明窗口)

## 会话恢复

贴图状态（位置、大小、透明度、层叠顺序、图片 dataURL）会被持久化到 `userData/ding-session.json`，按屏幕 displayId 分组。渲染进程在移动、缩放、调整透明度、置顶、关闭等稳定事件后标记脏位，由 2.5 秒间隔的 `ding:session:save` 批量写入；主进程校验并限制每组最多 24 张、单张不超过 12MB。

应用启动时若存在未消费的会话，主进程会创建贴图窗口（`ensureDingWindows`），每个渲染进程通过 `ding:session:get` 拉取本屏幕的贴图并恢复。会话采用读取即消费模型；若屏幕 ID 变化（显示器拔插），孤立贴图会合并到第一个请求的屏幕上。非 data:image 来源（如翻译贴图）不持久化。
